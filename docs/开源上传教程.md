# 把源码传到开源 Git

这份是给作者自己看的。

## 当前项目以后怎么更新

当前项目已连接到 [GitHub 仓库](https://github.com/drkk5282-gif/Infinite-Canvas-Open-Source-Project)，分支为 `main`。在项目文件夹里打开 PowerShell，每次改完按顺序执行：

```powershell
git status
git add .
git diff --cached --stat
git commit -m "写清楚这次改了什么"
git push
```

`git add` 把改动放进待提交列表，`git commit` 在本机保存一个版本，`git push` 才会把版本上传到 GitHub。提交前检查列表，确保没有 API Key、个人数据和压缩包。没有改动时，无需重复提交。

这个目录已经初始化过，不必再执行 `git init`、`git remote add` 或重新创建仓库。本项目单独设置 Git 作者信息，使用 GitHub 的 noreply 邮箱，不影响电脑上其他项目。

如果 GitHub 连接报错，可先检查本机代理是否已启动；本仓库使用系统代理地址 `127.0.0.1:7460`。以后代理端口变了，可用 `git config --local http.proxy http://127.0.0.1:新端口` 更新；不再使用代理时执行 `git config --local --unset http.proxy`。

以下步骤留给在其他目录从零开始上传的情况。

## 先准备这些

1. 一个账号。国内访问稳就用 [Gitee](https://gitee.com/)，国外常用 [GitHub](https://github.com/)。两个都要先注册并登录。
2. 本机安装 [Git](https://git-scm.com/download/win)。装完打开新的命令行，输入 `git --version` 能看到版本号。
3. 告诉 Git 你是谁（只在本机设置一次，把名字和邮箱换成你自己的）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

4. 确认这三样没有被打进提交：
   - `data/`（画板和 API Key）
   - `.venv/`
   - `.env`
   项目里的 `.gitignore` 已经写了这些。上传前还可以在文件夹里搜一遍 `sk-`、`api_key`，看到自己的密钥就不要提交。

## 在网站上建仓库

GitHub 或 Gitee 点「新建仓库」。

- 仓库名可以用 `infinite-canvas`，或你喜欢的英文名。
- 描述写一句：个人漫剧用的无限画布，仅供学习与非商业使用。
- **不要**勾选「用 README 初始化」。本机已经有 README、LICENSE 和免责声明，网站再生成一份会冲突。
- 许可证选「无」或 Other。本项目用的是自己的个人非商业约定，不是 MIT，也不是 GPL。网站上的标准许可证列表对不上，以仓库里的 `LICENSE` 和 `DISCLAIMER.md` 为准。

建好后，页面上会有一个地址，类似：

```text
https://github.com/你的用户名/infinite-canvas.git
```

或：

```text
https://gitee.com/你的用户名/infinite-canvas.git
```

先不要关这个页面。

## 在项目目录里执行

用命令行进入本项目文件夹（有 `run.py` 和 `README.md` 的那一层），然后：

```bash
git init
git add .
git status
```

`git status` 里如果出现 `data/`、`.venv/`、`.env`，停下来，不要继续。先检查 `.gitignore` 再重新 `git add`。

确认列表里是源码、文档和脚本之后：

```bash
git commit -m "公开个人漫剧画布源码，仅供非商业使用"
git branch -M main
git remote add origin 这里换成你刚复制的仓库地址
git push -u origin main
```

第一次推送会弹出登录。GitHub 现在要用 Personal Access Token，不能用账号密码。在 GitHub → Settings → Developer settings → Personal access tokens 里生成一个有 `repo` 权限的令牌，密码框粘贴令牌。Gitee 可以在设置里开私人令牌，推送时同样粘贴。

推送成功后，刷新仓库网页，应能看到 README。

## 以后改了代码再更新

```bash
git add .
git status
git commit -m "写清楚这次改了什么"
git push
```

每次 `git status` 都看一眼，不要把 `data/` 加进去。

## 别人怎么拿到

把仓库网址发给对方就行。对方需要：

```bash
git clone 仓库地址
```

然后按 [使用教程](使用教程.md) 安装 Python 并双击 `start.bat`。

如果只想发一个压缩包、暂时不用 Git：把整个项目打成 zip，但先删掉或排除 `data/`、`.venv/`、`dist/`。压缩包里要保留 `LICENSE` 和 `DISCLAIMER.md`。
